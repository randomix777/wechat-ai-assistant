# 商户软件使用说明：从双击到整理出订单

本文面向**不懂电脑的商户**。不需要命令行，不需要环境变量，不需要填群名，
不需要 API Key。

---

## 1. 启动

便携版解压后双击“启动威信AI智能助理.bat”；源码开发时可运行
`python -m wechat_ai_assistant.merchant_app`。

```
数据目录：便携版使用 EXE 同级的 `data` 文件夹；源码运行使用 `%LOCALAPPDATA%\wechat-ai-assistant`。旧版便携版首次启动时会把已有 `%LOCALAPPDATA%\wechat-ai-assistant` 或 `%LOCALAPPDATA%\pyweixin` 数据复制到 `data`，原目录保留。
本机名称：DESKTOP-XXXX
本地订单库：已就绪
微信状态：waiting_scan
已登录产品账号：否
本地订单查看、人工修改和导出不需要网络。

**本软件不会向微信发送任何消息。** 它只读消息、整理、记单、导出。
```

也可以先只做自检，不打开界面：

```powershell
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe -m wechat_ai_assistant.merchant_app --check
```

## 2. 第一次使用（向导：第 0 步～第 4 步）

> 向导步骤的**顺序、编号、标题只由一处给出**：`src/wechat_ai_assistant/wizard.py` 的
> `WizardStep.STEP_SPECS`。登录是进入向导前的门槛，不占步骤编号。

### 登录前置：产品账号

点「立即登录」会在浏览器里打开产品页面，在那里确认「是这台电脑」即可。
界面上**不会显示任何 Key 或地址**。

未登录时软件会先显示简洁的登录页面；登录成功后直接进入第 0 步。已登录的机器启动后
也停在**登录页**（那一屏写着「已经登录」和剩余额度），点一下「下一步」才进向导 ——
每次打开都从头看一眼，不会因为账号是自动恢复的就换了落脚点。登录是「智能整理」的前提。

### 第 0 步　检查微信

软件会区分七种状态，每种都有明确的中文提示：

| 状态 | 界面显示 | 您要做的 |
| --- | --- | --- |
| 未安装 | 未检测到电脑版微信 | 先安装 4.0 及以上版本 |
| 未启动 | 微信还没有打开 + **打开微信** 按钮 | 点按钮，然后在微信里登录 |
| 等待扫码 | 请在微信窗口扫码 | 在**微信官方窗口**扫码 |
| 等待手机确认 | 请在手机上确认登录 | 在手机微信点确认 |
| 已登录 | 微信已登录 | 无需操作，自动进入下一步 |
| 离线 | 微信显示网络不可用 | 先恢复网络再点「重新检测」 |
| 无法读取 | 暂时无法读取微信界面 | 退出微信重开；不行就重启电脑 |

**软件不会把微信窗口弹到最前面，也不会动您正在输入的内容。**
被动检测只查询，不移动、不置顶、不激活窗口。只有您点「打开微信」时才会主动启动微信。

已经登录时**不会要求重新扫码**。

### 第 1 步　选择会话

自动列出微信当前能看到的最近会话，支持按群聊/联系人切换、刷新。

- 勾选要读历史的会话（可多选）
- 第一版实时接单**只选一个**，在下一步里定

同名会话按群人数区分，例如「鲜果批发群（128人）」和「鲜果批发群（256人）」。
执行前还会再核对一次，核对不上就拒绝操作。

> 这里只列出微信当前能看到的最近会话，**不等于**您的全部联系人和全部历史。
> 想读更早的消息，请先在微信里往上翻一翻再读取。

**这一屏就是读取范围**（以前要再多点一屏确认，现在并进来了），下面两个按钮二选一：

- **更新消息**：只读上次之后的新消息（第一次用等同于全读）
- **读取全部**：把所选会话的消息这次都读一遍

上次选过的会话会显示成已勾选，不用每次重新挑。不满意就改了勾选再读。
如果提示本机数据库还读不了，点这一屏的「刷新列表」会自动提取密钥，提完再读。

### 第 2 步　读取历史消息

读取时显示进度条和逐会话明细，可以随时取消；中途关掉软件，下次启动会从断点继续。

读取历史时软件要在本机解密微信的数据库文件，比较占机器，**读完前请先别做别的事**
（这期间也别关微信，关闭中的数据库文件读到一半会不完整）。

读取完成后会明确告诉您实际读到了什么：

```
实际读到 22 条，时间范围 2026-09-25 至 2026-09-27
注意：社区团购 可能还有更早的历史没有读到
```

**不会把固定条数冒充成时间范围。** 撞到条数上限时会如实提示可能不完整。

读到的明细（每个会话的条数、状态、有没有缺口）就画在这一屏上。**先看清读到了什么**，
再点「下一步」去整理 —— 整理会花额度。不满意就点「上一步」回第 1 步改勾选或换读取方式。

### 第 3 步　智能整理

选好整理角色后点它自己的按钮（订单助手是「开始识别订货意向」，活动助手是
「开始整理活动信息」，通用整理是「开始整理群聊事项」）。**三个角色都调用 AI**：
选哪个角色，花的都是您账号里的分析用量。分析过程中这一屏会实时显示模型正在写的
内容；跑完的结果会显示处理条数、生成订单数、需要核对的条数。

**每个角色各自记进度**，一次最多带 200 条消息：

- 同一个角色再跑：只分析上次之后的新消息（第一次取**最近**的一批）；
- **换角色**：会把同一批消息重新分析一遍，也就是按用量再结算一次 —— 想省钱就先挑好角色。

这一屏会显示**分析额度**（进度条 + 已用百分比，另有充值/续期按钮）。数字来自您的
产品账号：登录时拿到的那份先显示着，进这一屏时再在后台刷一次最新值（没刷到就
沿用旧的，不影响整理）。

额度不足时会显示：

```
分析额度已用完
请联系客服开通或续期。（本软件暂不支持在线付款，不会自动扣费）
```

**未接真实支付时明确使用人工开通，不模拟到账。**

额度不足**不会丢数据**：已经读到的消息保留在本地，开通后点开始整理的按钮
即可继续，不会重复读取，也不会重复扣费。

### 第 4 步　AI分析详情

跑完就停在这一屏：处理条数、生成订单数、需要核对的条数，以及这份结果的明细。
每一单都能追到 `request_id` / `job_id` / `run_id` / `order_id`。

角色整理（不建单）的报告也只在这一屏 —— 点「查看 AI 整理报告」看。报告按角色
增量生成：同一个角色再跑一次，只分析上次之后的新消息。**报告会存在本机**：
关掉软件再打开，首页上的「查看 AI 整理报告」还能把它调出来（同一角色只保留最新那份）。
如果这次没有新消息，软件会把上次那份报告直接端出来，并说明"这是上次的报告"。

**一次选了多个群/多个联系人时**，报告按会话分开：每个会话一个可折叠的块
（顺序就是您选的顺序，块上写着这个会话分析了几条），合并全文收在最下面。
选了一个会话就只是一段正文，不套折叠。

同一个会话消息很多时，软件会分成几批分别分析，**最后收成一份报告**
（不是把几段拼在一起）—— 这一步可能多花一次调用。

看完点「回到首页」。首页上也会留一句这次的整理结果。

## 3. 日常使用：首页

首页回答八个问题，不再是「待确认列表」：

| 位置 | 显示 |
| --- | --- |
| 当前状态 | 微信状态、当前会话、剩余额度 |
| 计数 | 今日订单、需要核对、**客户未确认**、**待核对付款** |
| 今日备货汇总 | 按商品聚合总数量、单数、涉及客户 |
| 底部 | 查看订单 / 云端会发送哪些信息 |

**客户未确认**和**待核对付款**是分开的两个数字。
客户没有回复，只会被记为「客户未确认」，**不会**被标为已确认，更**不会**被标为已付款。
客户声称「钱转了」会进入「待核对付款」，等人工核对收款。

### 「查看订单」那一屏

每一行是：订单号、客户、**来自**（这一单是从哪个群/哪个联系人的消息里来的）、状态、内容。
点一行能看完整内容。

**「来自」这一列要留意一个已知口径**：客户是**按名字认的** —— 同一个名字在不同群里
会被当成**同一个人**，两边的订单算在一起。所以「张姐」在批发群和团购群各下一单时，
您会看到两笔都写着客户「张姐」，只有「来自」那一列分得开。如果您确实有两个同名的客户，
请用不同的名字（或加后缀）区分，否则他们的历史订单会互相影响
（比如「老样子」引用的历史订单可能来自另一个群）。

这一屏列的是**需要您处理**的订单（待核对、取消待核对）；系统自动记下的单（已自动记单）
不在这里逐条列出，它们已经按商品汇总到首页的「今日备货」里了。

## 4. 只读，不发消息

**本软件不会向微信发送任何消息，也没有「自动回复」这项功能。**

它做的是：读消息 → 理解并整理 → 在本地记单 → 给您核对和导出。
写回微信、替您回客户这件事，软件不做，需要您自己在微信里回。

**数据与隐私**：首页最底部有一行「数据与隐私说明」，点开是完整说明（会发什么、
不会发什么、保存多久）。平时折着，不占版面。

这样做有三个直接好处：

1. 不会因为程序出错而把话发给错的客户；
2. 不会打断您正在输入的内容，也不会抢占您的电脑；
3. 微信里出现的一切，都是您自己发出去的。

## 5. 自动记单规则

常规订单**不需要**逐单确认。以下条件全部满足才自动记单：

1. 身份明确（由本地系统绑定，模型说出一个名字不算绑定）
2. 商品在您的商品目录里
3. 数量存在、为正、未超上限
4. 单位与目录一致
5. 没有未解决的重复消息候选
6. 改量/追加/取消能唯一关联到一张订单
7. 引用的原文确实出现在消息里
8. 没触发金额、数量或履约异常

**模型自报置信度不作为依据。** 「老样子」找不到对应历史订单时不猜，转异常。

### 各类消息的处理

| 客户说 | 处理 |
| --- | --- |
| 「苹果两箱」 | 新单，自动记单（只在本地，不发消息） |
| 「老样子，明天送」 | 引用**该客户**的有效历史订单，按当前单价重新核价 |
| 「再加一箱苹果」 | 追加到当前未完成订单 |
| 「改成三箱」 | **改量**，不是追加三箱 |
| 「不要了」 | 取消，必须能唯一关联到一张订单 |
| 「苹果多少钱」 | 询价，**不建单**，也不需要确认 |
| 「钱转了」 | 进入「待核对付款」，**绝不标为已付款** |
| 闲聊 | 不插话 |

### 最多问一个问题

只有关键信息真的缺失时才问，且**最多问一个**。
按人实际会用的顺序找答案：

```
当前消息与引用 → 当前订单 → 该客户有效历史订单 → 您已认可过的默认规则
```

能从历史可靠推断的字段**不再问**。缺少非必要字段不阻止记单。

**缺少本机数据时不问客户** —— 那是系统该知道的，返回给软件补充。

## 6. 同一客户的连续消息会合并

一个客户连发好几条短消息（「苹果两箱」「再加一箱」「明天送」）时，软件按可配置的
窗口合并成一条来处理（默认 45 秒，最多等 90 秒），避免同一笔生意被拆成三单。

合并只影响**本地的理解**，不会给客户发任何东西。
